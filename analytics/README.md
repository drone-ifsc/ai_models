# analytics — инкрементальный бенчмарк моделей

Меряет для каждой модели репозитория **max FPS, загрузку CPU и пик RAM** и рисует
графики. Работает **инкрементально**: добавляет в CSV только те модели, которых
там ещё нет, а графики перерисовывает **только когда появились новые замеры**.

## Как гонять

```bash
# из контейнера ros-container (там есть ultralytics+ncnn, tflite_runtime, matplotlib):
python3 bench.py                 # найти все модели, домерить недостающие, обновить графики
python3 bench.py --threads 4     # только один thread-count (напр. под 4 ядра малинки)
python3 bench.py --list          # показать найденные модели и что уже в CSV, ничего не мерить
```

Добавил новую модель в репу (`*_ncnn_model/` или `*.tflite`) → просто запусти
`bench.py` ещё раз: он домерит **только её** и обновит графики. Уже посчитанные
модели пропускаются (см. лог `skip ... (already benchmarked)`).

Пересчитать всё с нуля (напр. частоты CPU были занижены power-saver'ом) —
удали `benchmark_results.csv` и запусти заново.

## Что где

- [`bench.py`](bench.py) — автодискавери моделей + оркестратор. Каждый замер
  идёт в **отдельном процессе** (чистый пик RSS через `ru_maxrss`).
  FPS = N/wall; CPU% = process_cpu/wall·100 (100% = одно ядро); RAM = пик RSS.
- [`make_charts.py`](make_charts.py) — перечитывает CSV и рисует графики
  (динамически, под любой набор моделей). Вызывается из `bench.py` автоматически.
- `benchmark_results.csv` — сырые числа (`name,kind,threads,input_px,dtype,fps,cpu_pct_across_cores,peak_ram_mb`).
- `01_fps.png` … `05_fps_vs_threads.png` — графики.

## Оговорки

- Модели дискаверятся по всему репозиторию: ncnn — по `model.ncnn.param`,
  tflite — по `*.tflite`. `imgsz` для ncnn берётся из `metadata.yaml`.
- Вход — случайный шум нужного размера; compute тот же, что на реальных кадрах
  (свёртки не зависят от контента), меняется только постобработка детектора.
- Числа привязаны к **машине, где гоняли** (см. `nproc`). На малинке (4 ядра)
  FPS будут кратно ниже, но соотношения между моделями сохранятся. Для честного
  сравнения при разных `input_px` смотри `04_throughput.png` (MPix/s).
- `ncnn` берёт своё число потоков сам (~все ядра) почти независимо от `--threads`;
  для tflite `--threads` = `num_threads` интерпретатора.
